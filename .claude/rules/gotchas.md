# Known Gotchas — digest

Always loaded. One entry per gotcha: how it shows up, what is actually wrong, what to do. **The full text — diagnostics, measurements, incident history — is `docs/gotchas.md`; read the matching entry before debugging one of these.** Numbers are permanent and shared with that file (code comments cite `gotcha #N`); gaps are intentional and two entries share #20.

## Audio capture

**#2 — The sox+BlackHole fallback was REMOVED. Do not re-add it.** Recording now refuses to start where it used to record silence, and that is intended. BlackHole is a cable, not a source: it carries nothing unless output is routed into it, which the app can neither do nor verify. Over 58 sessions it engaged once and lost that meeting. Any replacement must *prove* it captures real audio before the meeting. `recorder.js` → `resolveSystemCaptureMethod()`, `sckSilentWarning()`, `watchSckStartup()`.

**#5 — SCK delivers zero-filled frames.** `system.wav` is the right size, `sox <f> -n stat` reads max amplitude `0.000000`, and nothing errors. Cause A is Rogue Amoeba's `ARK.driver` starving the display mix. Cause B is a wedged long-running `coreaudiod`, fixed by `sudo killall coreaudiod` (it relaunches), which is often THE fix. ARK being loaded is a lead, not a verdict: timeline the last-good and first-broken sessions against `git log`, reboots and `coreaudiod`'s start time. If the helper starts the stream without exit 2 or `-3801`, permission is fine and this is starvation. ⚠️ The full entry's per-app-filter fix is itself #15, and its BlackHole bypass no longer exists (#2).

**#15 — The per-app `SCContentFilter` (`.including`) records digital silence, and it was introduced as the fix for #5.** Measured 2026-08-14 with ARK loaded throughout: `.including` read `0.000000` in every case, `.excluding` read `0.014282`. Three meetings were lost this way. `.excluding` ships, and `--filter-shape including` is a diagnostic only. Which shape works has changed twice, so **A/B it; don't reason about it.** `afplay` is invisible to `.including` but captured under `.excluding`, so an `afplay` zero proves nothing only under `.including`. `AudioCapture.swift` → `FilterShape`, `buildFilter()`, `refreshFilter()`.

**#16 — Nothing checked that the audio was audio.** Every health check measured file GROWTH, and a zero-filled WAV grows at the byte rate of speech. Now `_readPeak` (tri-state; `null` never means silence) → `SignalWatcher`, which reaches a verdict only once the mic has proven signal. `measureWavPeak` at processing time sets `manifest.tracks.system.silent` → red badge + a deterministic warning on the note. `health` (growing) and `signal` (audio) are independent; the losing pair is `live` + `silent`. There is one silence threshold (`SILENCE_PEAK_THRESHOLD === DEFAULT_SIGNAL_THRESHOLD === 4`), because at 0 a single stray LSB read as audio. `stop()` *measures* the file (`resolveFinalTrackStatus(…, {measuredSilent})`), because a restart resets the track status. **Coverage gap**: single-track gets no passive verdict and has no restart path. Deleting the `mode !== 'dual'` check yields warnings that recover nothing; extending it means building a restart path for `Recorder`. Never judge silence from a level of `0` or from `trimSilence`'s `allSilence`.

**#17 — The probe is meaningful only in a QUIET capture, and it rides on the filter shape.** Under broadband noise it false-positives, and under loud audio it is masked. That is harmless only because `verifyCapture` checks for real audio first, so never let a probe result decide on its own. It plays through `afplay`, which only `.excluding` can hear. After any filter-shape change, a universal "dead" verdict with working audio means the probe is invisible, not that capture broke (`peak: 0` + dead is the real failure; `result.detection.tones` has the evidence). Amplitude is politeness, not sensitivity. `DEFAULT_MIN_RATIO` (40) comes from a distribution, so don't lower it against one sample.

**#4 — Orphaned sox after a crash or force-quit** keeps recording and starves a new session's mic. Check with `ps aux | grep -v grep | grep 'sox -t coreaudio'`: writers to more than one session dir are orphans. `pkill -9 sox` recovers. Quit drains children (invariant #21), but a crash or SIGKILL still bypasses that.

**#6 — "Both tracks silent" is almost always two independent failures** (#5 + #4), not one deep bug. Run the ritual in order: orphaned sox? → ARK loaded? → `sox <track> -n stat` on each track → does QuickTime capture the mic right now? Fix each independently, and propose no rewrites before the ritual is done.

**#1 — `system_profiler SPAudioDataType` parsing is indent-based**: device names sit at 8 spaces, properties at 10. Don't change the parsing in `utils/audioDevices.js` → `listInputDevices()`.

**#20 (SCK frames) — ScreenCaptureKit delivers frames on CHANGE, not on a clock.** A static window sends one frame and then nothing, so "the same picture N times" never fires. Debounce instead: hold the newest frame and treat the *absence* of a newer one for `stabilityMs` as settled. Only `SCStreamFrameInfo.status == .complete` frames are real (idle and blank ones encode as grey). A `CVPixelBuffer` dies with its callback, so render a detached `CGImage` inside it. `SlideCapture.swift` → `scheduleSettle` / `settle`, `FrameHasher.reduce`.

**#23 — The silence trim cut both ends and recorded one total, and a companion transcript missing the mic side was filed as complete.** `trimSilence` is trailing-only now (`edge: 'trailing'`, `leadingSec: 0`), so a track keeps its clock; never put a leading `silence` effect back into `trimSilenceArgs`. Companion mode checks Meeting Copilot's transcript against CXNotes' own `mic.wav` (`companionCoverage.js`). If the companion has no mic lines, or a ≥ 60 s stretch without one while own speech is ≥ 10 s, CXNotes transcribes its own mic and merges it in (`companion:<app>+own-mic`). If the clock won't fit, it runs its own full two-track transcription. The decision is recorded in `manifest.processing.transcription.companionCheck`. `transcriber.js` → `assessCompanion()`, `mergeCompanionWithOwnMic()`.

**#24 — Phone and FaceTime calls are invisible to ScreenCaptureKit, and the probe says the capture is fine.** The remote party is played by the daemon `avconferenced`, not an app; neither filter shape hears it (a voicemail greeting left nothing above -60 dBFS), while the start probe (`afplay`) passes. Only the ringback, played by the FaceTime app, gets through. Fixed additively by `call-audio-tap` (invariant #26). Landmines: tap-only aggregate (an output subdevice leaks the headset mic in); `.unmuted` only (`.mutedWhenTapped` mutes the call); with no `NSAudioCaptureUsageDescription` in the responsible app — including running the helper from a terminal — the tap returns zeros with no error and no prompt; the first-ever tap blocks about a minute on the prompt; AirPods change rate mid-call. `IsRunningOutput` means IO is running, not that it is loud.

## Environment & packaging

**#14 — A Dock-launched app has no Homebrew on its PATH** (`/usr/bin:/bin:/usr/sbin:/sbin`), so a bare `which`/`spawn` finds nothing. A terminal `open -a` passes your shell's PATH through, so whoever builds the app never sees it. Always use `resolveBinary()` (invariant #20). Reproduce a real launch with `env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin HOME="$HOME" /Applications/CXNotes.app/Contents/MacOS/CXNotes`; `/ship` step 7 checks this. Don't bundle a bare `whisper-cli`: it links six `@rpath` dylibs and would dyld-crash.

**#18 — "Run Setup" was dead in packaged builds, and the dependency check didn't know Parakeet existed.** In a package, `__dirname` is inside `app.asar`, which is a file. `resolveSetupCommand()` runs `cd repo && ./setup.sh` in dev and `bash "<Resources>/setup-packaged.sh"` (brew + curl only) when packaged. Transcription is OK if either Parakeet (`findUv()`) or whisper is present (`resolveTranscription()`). `brew install whisper-cpp` ships **no model**; download it into `~/Library/Application Support/CXNotes/models/`.

**#3 — whisper.cpp needs `ggml-base.en.bin`.** `setup.sh` downloads it (`setup-packaged.sh` for installs). `services/transcriber.js`.

**#7 — The Calendar prompt is fired by the `calendar-helper` binary and keyed to its code signature.** A build signed differently re-prompts. The helper's `Info.plist` needs both `NSCalendarsUsageDescription` and `NSCalendarsFullAccessUsageDescription`, or the prompt never fires on 14+. Sign the helper with the parent app's identity.

**#8 — An MCP-spawned `calendar-helper` can't inherit the app's grant**: it has a different signature, and a headless spawn returns denied without prompting. `resolveCalendarHelperPath({preferInstalled: true})` prefers `/Applications/CXNotes.app/Contents/Resources/calendar-helper`. `npm run mcp:check` diagnoses it (exit 0 ready / 1 helper missing / 2 not granted).

## Calendar & summarisation

**#9 — cxmail's DB is foreign, per-mailbox and inconsistent about dates.** It stores one row per invite × mailbox (up to 4×). Reschedules share an `event_uid`, and RSVPs arrive as separate `METHOD:REPLY` rows. `dtstart` is UTC `Z`, floating local, or floating with a `TZID` in `raw_ics`, and `detected` rows have no `dtend` (synthesise +60 min). Keep precision and dedup in JS, and keep the SQL window coarse (`now - 1 day`), because tightening it skews by your UTC offset. Schema drift must surface as a typed error, never a throw. Fewer events than rows is expected. `cxmailCalendarSource.js`.

**#21 — A mail-derived calendar can't see invitees who didn't RSVP to a meeting YOU called.** You only receive their `METHOD:REPLY`s, one attendee each. No parsing change can fix that, because the message doesn't exist. `calendarSources/attendeeMerge.js` unions EventKit's roster in: additive only, and it refuses ambiguous matches.

**#12 — LLM CLIs print refusals to stdout with exit 0.** A usage-limit notice, or a bad-model message (`claude -p --model bogus` exits 0), became the "summary", badged Summarised and filed. `detectProviderFailure(output, provider)` runs in both wrappers. Auth patterns match at any length; limit and model patterns match only when the output is ≤ 400 chars AND has no `##` heading. **Never widen the patterns without that gate**, which is what keeps a summary *about* rate limits. Recover by re-summarising from the existing transcript (✨ / panel Retry), never a full reprocess. `detectPoisonedNote()` flags old notes. Exercise the real CLIs when touching this path.

**#20 (speaker names) — The careful path went quiet and the careless one answered in its place.** `speakerNames.js` correctly rendered nothing, but the invite roster was rendered as `- Participants:` next to a section to fill in, so the note asserted attendance. Two paths fed one sentence and only one had the guard; for any safety property, ask what else reaches the same output. `meetingContextBlock.js` labels the roster "Invited (NOT an attendance record)" and warns that a one-off name matching nobody invited is probably a mis-transcription.

## Frontend

**#13 — A comma-separated RGB triplet kills the whole background, and the result looks better than the fix.** `rgb(28, 26, 23 / 0.7)` is invalid, so the declaration drops, the pane paints nothing, and bare vibrancy looks like excellent glass. **Never judge a pane by eye.** Read `getComputedStyle(el).backgroundColor`: `rgba(0, 0, 0, 0)` on a pane that declares a background is the bug (on `body` and wrappers it is correct). Use space-separated triplets for `rgb(var(--x) / var(--a))`. The comma `--accent-rgb` token is the other convention (`rgba(var(--accent-rgb), a)`); never mix the two.

**#19 — `el.hidden = true` does nothing on an element an author rule gives a `display`**, because author origin beats the UA `[hidden]` rule. The red "No system audio" warning showed on every recording. Any rule that sets `display` on a hideable element needs `.x[hidden] { display: none; }` (`.no-audio` and `button.who-more` in `menubar-panel.html`). Check `getComputedStyle(el).display`, not `el.hidden`.

**#10 — `tray.getBounds()` returns off-screen coordinates when the menu bar is auto-hidden** (seen: x = -9294). Validate against `screen.getAllDisplays()`, fall back to the top-right of the cursor display's work area, and clamp both axes (`panelAnchorFor()`, `positionMenubarPanel()`). The panel's `blur` fires before the tray `click`, hence `panelClosedAt` / `PANEL_REOPEN_GUARD_MS`.

**#11 — `.form-group label { display: block }` (0,1,1) beats `.checkbox-label` (0,1,0)**, which silently kills the switch layout. Scope rules as `.form-group .checkbox-label` (children too) rather than using `!important`. Measuring a `display:none` pane returns zeros, so switch to the pane first.

**#22 — Return does nothing on a focused button while Option is held.** Chromium sends no `keypress` with Alt down, and a button's activation rides on `keypress`. Activate from `keydown` instead (Enter/Space → `preventDefault()` + `btn.click()`), which also keeps the plain case single-fire. `menubar-panel.html` → the `noteMenu` keydown handler.

## Maintaining this file

For a new gotcha, write the full entry in `docs/gotchas.md` and a digest of a few lines here under the next free number. When one is resolved, mark it `~~SUPERSEDED~~` in both files. Never renumber. The size budget and the number parity between the two files are enforced by `scripts/instruction-budget.test.js`.
